# 06 · Launch Checklist (visibility · lowballs · deposits & scope changes)

> Fewer common pits.  
> **Does not include** any guidance on fake reviews, review trading, account abuse, or fabricated sales.  
> No guarantee of impressions or closes — those track account health, niche, pricing, and execution.

---

## 1. Low visibility — check in this order

Before blaming “the algorithm,” run self-checks:

### 1) Can people find and understand the gig?

- [ ] Title front-loads a searchable **skill / deliverable**
- [ ] Description first screen states delivery — not a long bio
- [ ] Category matches the real service
- [ ] Cover / thumbnail reads as a **service**, not a random image

### 2) Are you filtering yourself out?

- [ ] Price with no scope → careful buyers ghost; vague buyers fight later  
- [ ] Overpromises → skeptical buyers bounce  
- [ ] No decline list → junk inquiries burn time and energy  

### 3) Ops habits

- [ ] Thrashing title / pausing–unpausing many times a day → change, then observe  
- [ ] Ignoring inquiries → worse conversion later  
- [ ] Many near-duplicate gigs → merge into one or two clear offers  

### 4) Expectations

- [ ] New gigs with few reviews often start slow — take 1–2 clear small Standard jobs first  
- [ ] **Do not** buy fake reviews to “look busy” — prohibited; this kit will not discuss how  
- [ ] When visibility is weak, fix **keywords + first screen + reply speed**, not gray-hat tricks

## 2. Student / ultra-low budget — decline without a fight

### Principles

- Respect budget; **don’t accept loss-making unlimited edits**  
- Offer a **smaller scope** instead of only saying “too cheap”  
- End threads that demand free drafts, unlimited rounds, or outcome guarantees  

### Scripts

1. **Shrink scope:**  
   “Budget noted. I can do Basic: only `[minimum scope]`, 1 light round, `$__`. Full Standard isn’t available at that number.”

2. **Stop cutting:**  
   “That’s below my time cost and would waste both of us. Please find a better budget match, or come back when Standard fits.”

3. **Optional student note:**  
   “Student / tight-budget work is Basic only, brief locked once; no rush and no heavy redesigns. If that works, confirm Basic; if not, totally fine.”

4. **Close the loop:**  
   “Scope and price are clear. If it doesn’t work, I’ll free both our calendars — good luck.”

### Decline immediately if they ask for

- Homework / exam proxy work  
- “Do ten free versions then maybe pay”  
- “Also leave me a fake review”  
- Forgery, IP theft, or false advertising

## 3. Deposits, start, and scope changes

### 1) Money → start (adapt to platform; common safe shape)

```text
Lock scope + price → order / pay per platform → I confirm → schedule → revise by rounds → deliver final
```

Spell out in the gig:

- When the clock starts (after scope lock / after payment clears)  
- Revision rounds and reply windows  
- What happens if the buyer goes silent (e.g. pause, or treat as accepted after X days)  

### 2) Scope-change scripts

5. **Name the change:**  
   “This is a scope change (`[style swap / more volume / earlier date]`), outside the original quote. Add-on `$__`. Confirm to proceed; otherwise I finish original scope.”

6. **Don’t keep building into a dispute:**  
   “Big change — I’ll pause at a deliverable original-scope state. After you confirm the new quote, I’ll add the new part.”

7. **Paid, then endless edits:**  
   “Rounds are used. More edits are `$__/round` or a new order. Or we can close on the current final.”

### 3) Deposit pitfalls

- [ ] Large custom work: no clear scope → no take payment / no start  
- [ ] Never verbally promise “all future changes included”  
- [ ] Keep chat on-platform when you can  
- [ ] Say early if you can’t do invoices / contracts / company process  
- [ ] In disputes, point to the **written scope list**, not feelings  

### 4) Mini scope confirmation (send for a “confirm” reply)

```text
[SCOPE CONFIRMATION]
Use case:
Deliverable & formats:
Includes:
Excludes:
Revision rounds:
Delivery timing:
Price:
Change rule: more volume / style swap / earlier date → re-quote
Reply “confirm” and I start after the platform order/payment step.
```

## 4. Other frequent pits

| Pit | Better habit |
|-----|--------------|
| Description reads like a résumé | Deliverable list + flow + declines |
| Improvising every inquiry | Keep `03` scripts; change numbers and send |
| Accepting work far past skill | Decline; one-line redirect is enough |
| Trading free unlimited work for a review | Reviews are optional; boundaries stay written |
| Pasting a competitor’s listing | Duplicate/IP risk — rewrite from the skeleton |
| Wanting fake reviews for traction | **Forbidden** — no methods discussed here |

---

## 5. Non-negotiables (pin in Notes)

1. No fake reviews; no gray-hat coaching.  
2. No homework / exam proxy work.  
3. No invented sales or case studies.  
4. Unclear scope → no hard price, and don’t start.  
5. Changes get re-quoted; outside rounds → pay more or close.
